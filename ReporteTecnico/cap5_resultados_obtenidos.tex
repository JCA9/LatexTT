\chapter{Resultados Obtenidos}

En este Trabajo Terminal se concluyó el desarrollo e integración del sistema FINARA en su totalidad. A diferencia de la etapa anterior, en la que los resultados correspondían al análisis, diseño y planificación, los resultados del presente trabajo son los artefactos funcionales del sistema: la aplicación móvil, la plataforma web y el servidor backend, integrados y operativos como un sistema unificado de gestión financiera personal.

% ──────────────────────────────────────────────────────────────
\section{Sistema integrado y funcional}
% ──────────────────────────────────────────────────────────────

El principal resultado del presente trabajo es un sistema completo y funcional compuesto por tres componentes que operan de manera coordinada:

\begin{itemize}
  \item \textbf{Aplicación móvil} desarrollada en Flutter, orientada al
    registro ágil de gastos e ingresos, escaneo de tickets físicos
    mediante la cámara del dispositivo y seguimiento de presupuestos y
    deudas desde cualquier lugar.

  \item \textbf{Plataforma web} desarrollada en Next.js y React,
    orientada al análisis financiero detallado, la visualización de
    gráficas comparativas, la generación de reportes exportables y la
    consulta de recomendaciones personalizadas por período.

  \item \textbf{Backend REST} desarrollado en Node.js y Express,
    encargado de centralizar la lógica de negocio, gestionar la
    persistencia en MySQL, orquestar el pipeline de OCR y proveer
    recomendaciones mediante inteligencia artificial.
\end{itemize}

Los tres componentes se comunican a través de una API REST autenticada
con JSON Web Tokens, lo que garantiza el aislamiento entre cuentas de
usuario y la coherencia de los datos entre plataformas.

\subsection{Backend y API REST}

Se implementaron once módulos en el servidor backend, exponiendo más
de sesenta endpoints documentados:

\begin{itemize}
  \item Módulos de autenticación, usuarios, categorías, ingresos,
    gastos, presupuestos, deudas, alertas, tickets y dashboard.
  \item Módulo de recomendaciones con integración a Claude Haiku y
    sistema de caché de quince días.
  \item Sistema de tareas programadas (cron jobs) para recordatorios
    diarios y rollover mensual automático de presupuestos e ingresos
    recurrentes.
  \item Base de datos MySQL con doce tablas normalizadas a 3FN y
    relaciones de integridad referencial con eliminación en cascada.
\end{itemize}

\section{Pipeline de OCR}
% ──────────────────────────────────────────────────────────────

El módulo de reconocimiento óptico de caracteres es el componente
técnicamente más elaborado del sistema. Se implementó un pipeline
de seis etapas que combina procesamiento local y servicios externos:

\begin{enumerate}
  \item \textbf{Preprocesamiento:} Corrección de iluminación,
    reescalado, corrección de perspectiva (deskew) y binarización
    adaptativa mediante OpenCV.
  \item \textbf{Extracción con Tesseract:} OCR con modo LSTM en
    modo de bloque de texto (PSM 6), con soporte para los idiomas
    español e inglés.
  \item \textbf{Evaluación de confianza:} Cálculo de una métrica
    ponderada que combina la confianza reportada por Tesseract con la
    presencia detectada de campos clave (total, productos, tienda, fecha).
  \item \textbf{Compuertas de activación:} Si la confianza es inferior
    a 0.72 o el número de palabras reconocidas es menor a 15
    (compuerta técnica), o si no se detectaron ni total ni productos
    (compuerta estructural), el flujo escala al servicio externo.
  \item \textbf{Respaldo externo:} Google Cloud Vision extrae el texto
    completo del documento; Claude Haiku lo estructura en JSON con los
    campos requeridos.
  \item \textbf{Categorización automática:} Los productos detectados
    reciben una categoría sugerida mediante un clasificador por palabras
    clave y por similitud con el historial de compras previas del usuario.
\end{enumerate}

Este diseño híbrido permite procesar la mayoría de los tickets
localmente —sin costo de API externa— y escalar únicamente los casos
de mayor dificultad a servicios de visión artificial en la nube.

\section{Recomendaciones financieras con inteligencia artificial}
% ──────────────────────────────────────────────────────────────

Se implementó un módulo de recomendaciones financieras personalizadas
que utiliza Claude Haiku como modelo de análisis. Para cada período
consultado, el sistema recopila el contexto financiero del usuario
(ingresos, distribución de gastos, estado de presupuestos y deudas) y
genera un análisis estructurado con cuatro secciones: resumen textual,
riesgos identificados, recomendaciones accionables y acciones sugeridas
priorizadas.

Un sistema de caché con vigencia de quince días evita llamadas
redundantes a la API del modelo para el mismo período, reduciendo el
costo operativo y garantizando tiempos de respuesta consistentes. Ante
una falla del servicio externo, el sistema retorna automáticamente un
conjunto de recomendaciones generadas por reglas locales, asegurando
la disponibilidad del módulo en todo momento.

\section{Cumplimiento de requerimientos}
% ──────────────────────────────────────────────────────────────

De los cuarenta requerimientos funcionales definidos en la etapa de
análisis, todos fueron implementados en el presente trabajo terminal.
Los cinco requerimientos no funcionales —seguridad, mantenibilidad,
portabilidad, compatibilidad y usabilidad— fueron satisfechos mediante
las siguientes decisiones de implementación: cifrado de contraseñas con
bcrypt (factor 12) y autenticación JWT para seguridad; arquitectura
modular y repositorio en GitHub para mantenibilidad; soporte para
Android 10 o superior para portabilidad; validación en Chrome, Edge y
Firefox actualizados para compatibilidad; y adhesión a Material Design
y las guías de accesibilidad de React para usabilidad.
